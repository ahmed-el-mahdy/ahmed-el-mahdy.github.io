Change controls

Approach: Separate infrastructure, identity, data, workload, route, and portal gates. Preserve legacy staging and move one API at a time.

Validated: The September handoff records six backend Deployments, two smoke-tested portals, exact CSI key coverage, and removal of temporary access and copy resources.

Boundary: Authenticated UAT and notifications remained follow-ups. The historical Gateway API handoff differs from October NGINX source; current controller ownership needs reconciliation before reuse.

Data integrity

File migration under network controls

Replicated 91,724 application blobs across three containers using bounded SDK streaming after CLI and service-side copy attempts failed. Kept source access read-only and excluded target delete permissions.

Blob StoragePython SDKNetwork boundariesInventory parity
Migration checks

Approach: Pilot one blob, then a small container, before using 24 bounded workers for the larger data set. Preserve metadata, content settings, and tier; do not overwrite matching objects.

Validated: Exact name/size parity for 91,724 objects and 12,244,349,406 bytes at the checkpoint. Temporary Jobs, pods, and SAS Secrets were removed.

Boundary: This was a name/size comparison, not a content-checksum audit. The source remained writable, so parity was time-bound and required a delta gate before cutover.

Validation and recovery

Approach: Treat RU/serverless and vCore as separate targets. Trace workload egress rather than assuming a healthy resource is reachable from a pod.

Validated: Recorded data checks for the RU stage and real application reads after the vCore connection cutover, with source and connection recovery anchors retained for the agreed window.
